# UMAMETRY — 실제 이용 관점 상용 품질 진단·전면 개선안

작성: 2026-09-05. 대상: 현재 열린 우마윈즈 프로젝트의 `site/`와 해당 공개 v28. 최신 사용자 요청에 따른 **분석·제안 보고**다. 제안을 아직 제품에 적용하거나 인터넷에 공개하기(배포)하지 않았다. 이전 작업의 미공개 홈 후보·사용자 변경·이력은 보존했다.

## 먼저 읽을 결론

**지금 UMAMETRY를 “문제없이 쓸 수 있는 성숙한 무료 상용 서비스”라고 평가할 근거는 부족하다.** 기능별 코드와 설명은 많이 있지만, 사용자가 자신의 실제 판단을 정확히 기록하고, 결과를 복기하고, 다음 판단에 적용하고, 문제가 생겼을 때 복구·도움을 받는 전체 경험이 연결되지 않았다. 이번 점검에서 그 이유를 구체적인 소스·공개 화면·합성 검사로 확인했다.

단순히 버튼 색이나 홈 배치를 바꾸는 것으로 해결되지 않는다. **제품의 약속과 자료의 의미 → 저장 안전성 → 핵심 사용 흐름 → 콘텐츠 깊이 → 통일된 화면 → 실제 운영** 순서로 고쳐야 한다. 기존의 “자동 검사 200/200”은 이 전체 경험의 합격증이 아니다. 직전 미공개 새 홈도 한일 혼합 문구와 개발 지표 중심 구성이 남아 있어, 그대로 공개한다고 이번 요구를 만족시키지 못한다.

수정안은 **64개**이며, 출시 신뢰·자료·운영 조건 P0 11개, 핵심 품질 P1 49개, 완성도 P2 4개다. 이는 **64건의 실제 클릭 고장을 모두 재현했다는 뜻이 아니다.** 확인된 결함, 소스상 위험, 반드시 채워야 할 운영 조건을 구별했다. “1년 운영한 것 같은 완성도”를 위한 설계와 통과 조건을 제시하지만, 1년 운영 실적·무결함·시장 성과를 보장하지 않는다.

## 2. 사용자 불편이 생기는 핵심 원인

1. **실제 경주 분석을 기대하게 하지만 주 콘텐츠는 개발·합성 예시다.** 분석20개는 살아 있는 경주/결과 공급을 증명하지 않는다. 직접 기록도 실제 사용자 입력 상태가 없다.
2. **경주 전 판단이라는 정체성에 비해 구조가 평면적이다.** 명확한 경주·판정 명제·마감 시각이 기록 흐름에 부족하다.
3. **기능 페이지는 있지만 다음 행동으로 잘 이어지지 않는다.** 분석/학습의 입력 이동28곳, 복기 메뉴·작성 위치, 다음 규칙 재사용이 대표적이다.
4. **사용자가 안심할 수 있는 실패 상태가 부족하다.** 손상 자료를 빈 목록으로 보이게 하거나 저장 후 정리 오류를 저장 실패로 읽히게 할 위험이 있다.
5. **학습 카드의 양을 학습 가치로 오인하기 쉽다.** 요약·행동 한 줄로는 사용자가 사고 과정을 배우고 연습하기 어렵다.
6. **고객 화면에 내부 개발 상태가 너무 많다.** 준비도·검사 횟수·가격 가설·운영 설계가 실제 이용 흐름과 섞인다.
7. **안내 문장과 실제 구현의 보장 범위가 다르다.** 봉인·허가 자료·개인화·공유본 편집 불가·비밀 없는 내보내기 등의 표현을 고쳐야 한다.
8. **실제 지원과 운영 검증은 따로 남아 있다.** 개인정보/장애/복원에 대해 누가 답하고 책임지는지가 코드만으로 해결되지 않는다.

## 3. 특히 먼저 고쳐야 할 확인 사항

### 3.1 실제 확인된 이동 문제

분석 카드20곳과 학습8곳은 `/records?...#record-form` 또는 `/records#record-form`으로 보낸다. 실제 기록 form은 `className="record-form"`만 있고 해당 id가 없다. URL 자체는 열리지만 약속한 입력 위치로 가지 않는다. **28개 경로 고장이 아니라, 같은 앵커 결함의28개 노출 지점**이다. CM-11로 묶어 고치고 학습별 목적지도 재설계한다.

### 3.2 클릭은 가능해도 의미가 맞지 않는 것

- 숙련도·정보밀도: 추천 설명 문구는 바뀌지만 목적 화면의 정보량을 바꾸는 연결은 확인되지 않았다(CM-16).
- 일일 목표: 설정 저장과 실제 휴식/사용량 기능이 단절되어 있다(CM-18).
- 고급 검색: 전체 결과 수를 보여도50개 이후 기록으로 가는 길이 없다(CM-30).
- 복기 버튼: 선택만 바꾸고 아래 편집 위치로 안내하지 않는다(CM-10).
- 문의 준비: 진단 파일을 만들 뿐 실제 문의가 접수되는 기능은 아니다(CM-44).

### 3.3 실행 가능한 것처럼 오인하기 쉬운 비활성 기능

Google 로그인은 비활성이고 구성 미완료 사유가 노출된다. 현재는 주 행동에서 제외하는 편이 낫다. 설치 버튼은 초기 HTML에서 비활성이지만 브라우저 설치 이벤트에 따라 달라지는 것이므로 **고장으로 단정할 수 없다.** 자료0건인 리뷰 자료 저장과 동의 전 철회 버튼이 비활성인 것도 정상 상태일 수 있다. 모든 비활성 기능을 제거하는 것이 아니라 이유와 대안을 정확히 제공해야 한다.

### 3.4 집중 검사로 확인한 자료 문제

- 권리 증거 없이 `licensed` 정정 객체 생성 가능.
- `2026-02-31` 확인일 수용, 먼 미래 확인일 수용.
- 기록 생성 단계부터 봉인 시각 부여. 화면은 이를 미리보기에서 생성.
- 일반 설정 삭제 목록에 시작 설정2개 누락.
- 숙련도/밀도를 바꿔도 동일 목적 경로, 설명만 변경.
- 최근7일 식에 미래 기록 포함.

이는 메모리의 합성 객체만 사용한 검사다. 개인 기록 생성·정정·삭제·동기화는 실행하지 않았다.

## 4. 유지할 자산과 다시 열어야 할 계획

전면 폐기할 프로젝트는 아니다. 로컬 우선 기록, 정정/복기를 별도 사건으로 남기는 구조, JSON/CSV, 가져오기 검증, 공식 결과 정합을 위한 모듈, 선택형 동기화 경계, 광고·관리 기능을 준비 전 닫아 두는 방식, 합성 예시와 위해 경고는 재사용 가치가 있다.

다만 “로컬 완료 후보”였던 S1-003/006/010/012/014/015와 S2-001/002/003은 이번 발견 사항을 연결해 재검토해야 한다. CUX-M05의 학습센터 존재와 충분한 수업 제공, CUX-M07의 진행 표시와 실제 단계형 입력은 같지 않다. **기존 정본을 삭제하지 말고 결함 번호를 기존 요구사항에 연결해 재개방**하는 것이 안전하다.

이 보고서에서는 정본의 채택 상태를 임의로 바꾸지 않았다. 상세 명세에 연결된 S1/S2/CUX/CF 번호로 이후 수정 이력을 추적할 수 있다.

## 5. ‘1년 운영한 수준’을 이 프로젝트에 맞게 정의

이 표현에 공인된 단일 점수는 없다. 여기서는 다음을 모두 만족하는 실용 목표로 정의한다.

- 처음 온 사람이 서비스의 범위·자료 한계·첫 행동을 이해한다.
- 가입 없이 개인 기록을 만들고 재열고 복기할 수 있다.
- 연습 자료와 자기 실제 기록·공식 자료가 구별된다.
- 오류·오프라인·재시작·기기 변경에서도 데이터 상태를 알 수 있다.
- 복기가 다음 판단의 구체적 행동으로 이어진다.
- 콘텐츠는 읽을 설명뿐 아니라 완료 가능한 연습과 해설을 제공한다.
- 어느 페이지든 메뉴·문구·저장·취소·뒤로가기 규칙이 같다.
- 휴대폰·키보드·화면읽기에서도 핵심 과업이 끝난다.
- 문제가 생기면 실제 지원을 받고 운영자가 복구할 수 있다.
- 공개판·정책·자료·오류 상태가 날짜 있는 사실과 일치한다.

‘모든 고급 기능을 보여주는 것’보다 ‘지금 제공하는 기능을 끝까지 책임지는 것’이 우선이다. 그렇다고 법적 미확정, 실기기 미시험, 자료 권리 미확인을 화면에서 숨기자는 뜻은 아니다. 고객에게 필요한 한계를 간결히 알리고 내부 개발 문서와 분리한다.

## 6. 제품 범위를 먼저 정확히 고정

### 권장 첫 상용 범위: 직접 기록·복기·학습 서비스

운영자가 실제 경주 자료 계약을 아직 확보하지 못했다면 **사용자가 자기 판단을 직접 입력하는 무료 학습 도구**를 첫 완성 범위로 권장한다. 합성 연습은 별도이며 실시간 예측/공식 결과 자동수집을 제공한다고 말하지 않는다. 다만 이것은 원기획의 ‘허가된 경주 자료/공식 결과’ 출시 조건을 축소하는 결정이므로 **운영자가 범위를 채택해야 한다.** 이 보고서가 원래 조건을 자동 면제하지 않는다.

공식 자료형을 유지한다면 제공자 권리·경주 식별·시각·결과 정정·서비스 중단을 실제로 연결해야 한다. 출처 이름만 붙이는 것으로 대체하지 않는다. 두 방식을 섞지 말고 각 기록의 입력 출처와 서비스의 검증 여부를 분리한다.

계정·동기화는 선택 기능이다. 그러나 제공한다고 노출한 순간부터 로그인/만료/철회/충돌/삭제/복구까지 작동해야 한다. 미준비 Google 버튼과 실제 ChatGPT 인증을 한 계정처럼 보여서는 안 된다.

### 길찾기

PC는 `今日 / 記録 / 振り返り / 学ぶ`를 기본으로 하고 통계·고급 도구를 복기 안에 묶는다. 설정·지원·백업은 항상 찾을 수 있게 둔다. 모바일은 `今日 / 記録 / ＋記録 / 振り返り / その他`의5탭을 제안한다. 중앙 새 기록은 실제 작성 동작이고 현재 위치 표시는 나머지 화면 상태와 구별한다. 5탭 선택은 구현 후 사람에게 찾기 시험을 해야 하며 모양만으로 정답이라고 단정하지 않는다.

### 입력 3단계의 상세 계약

1. **무엇을 예측하는가:** 연습/직접 기록 선택, 대상 식별, “무슨 결과가 되면 일치인가”라는 명제, 예정/마감 시각과 시간대. 미확인이면 모른다고 쓸 수 있으나 사전 검증 표시는 제한한다.
2. **왜 그렇게 생각하는가:** 찬성 근거, 반대 근거, 자료 출처와 확인 시점, 불확실성, 확신도. 50을 무조건 추천값으로 넣지 않는다. 짧은 예시는 사용자가 선택해서 넣게 한다.
3. **무엇을 저장하는가:** 명제·근거·확신도·저장 위치·봉인 보장 범위 확인. 확정 순간에 기록 사건 생성. 성공하면 저장된 기록 상세와 `結果が分かったら振り返る`로 연결한다.

뒤로가기는 입력을 보존한다. 검토와 확정은 구분한다. 확정 뒤 원문을 조용히 편집하지 않는다. 데이터 이사(마이그레이션)는 기존 기록에 없는 경주·권리·명제를 추정해 채우지 않고 `미확인`으로 표시한다.

### 기본 문구 교체안

- Google 미구현: `この端末だけで利用できます。アカウント連携は準備中です。`
- 기기 저장: `このブラウザに保存しました。他の端末にはまだ同期していません。`
- 저장 거부: `端末に保存できませんでした。入力は画面に残っています。内容をコピーしてから再試行してください。`
- 자료 손상: `保存データを読み取れません。元のデータは変更していません。バックアップと復元方法を確認してください。`
- 내보내기: `あなたが入力した内容が含まれます。共有する前に確認してください。`
- 기록0건 통계: `まだ判断できる記録がありません。最初の一件を記録してみましょう。`
- QR: `サイトをスマートフォンで開きます。記録を移すにはバックアップの読み込み、または対応する同期設定が必要です。`
- 문의 준비 파일: `問い合わせ用の確認資料を作成します。この操作では送信しません。`

최종 공개 문구는 일본어 검수자가 읽어야 한다. 본 예시는 구현용 초안이지 번역 검수 완료본이 아니다.

### 시각 체계

본문은16px를 시작점으로 하고 충분한 줄간격을 확보한다. 제목 크기는 실제 첫 행동을 밀어내지 않도록 제한한다. 주 버튼1개/보조 버튼/파괴 행동을 구별하고 단순 카드 숫자를 줄인다. 핵심 터치 영역은44×44 CSS px를 제품 목표로 삼는다. 이는 WCAG 2.2 AA의 모든 버튼에44px를 강제한다는 뜻이 아니다. WCAG에는24px 최소 타깃과 예외 조건, 대비·키보드·초점·재배치·오류 기준 등이 별도로 있다. [W3C WCAG 2.2 기준](https://www.w3.org/WAI/WCAG22/quickref/)

화면 크기만 줄이지 말고 PC는 비교, 모바일은 한 과업씩 집중하도록 구성한다. 저장/취소/오류/로딩/빈 상태/오프라인의 공통 표시를 먼저 만들고 각 화면에 적용한다. 표의 기능상 필요한 가로 탐색과 페이지 전체의 우발적 넘침은 구분한다.

### 실제로 넣을 수업 내용의 예: 확신도70%를 어떻게 복기하는가

이 강좌는 합성 이항 명제 `A가 정해진 조건을 충족한다`를 사용한다. 경주 결과/이익 추천이 아니라 확률 평가 학습이다.

1. 결과를 보기 전에 확신도0.7과 찬반 근거를 남긴다.
2. 조건을 충족하면 y=1, 충족하지 않으면 y=0이다. 확인되지 않으면 계산에서 보류한다.
3. 점수는 `(p-y)²`. 충족한 경우 `(0.7-1)²=0.09`, 미충족은 `(0.7-0)²=0.49`다.
4. 이 두 건의 평균은0.29다. 한 건의0.09만으로 좋은 예측 서비스라고 평가하지 않는다.
5. 낮을수록 이 오차 기준에서는 좋지만, 서로 다른 사건 난이도·기본 빈도·선택 표본을 섞은 경쟁 순위로 바로 사용할 수 없다.
6. 연습: 0.6으로 예측했는데 미충족이면0.36. 결과 미확인인 두 번째 자료는0으로 계산하지 않는다. 틀리면 분모·미확인 제외를 설명한다.
7. 복기: 어떤 근거를 사전에 알 수 있었는지, 다음에 더 확인할 자료가 무엇인지 적는다. 실패했다고 임의로 다음 확률을50%로 강제하지 않는다.

이 정도의 설명·계산·오해 방지·연습이 각 핵심 수업에 필요하다. 장기 통계는 실제 사용자 자료를 확보하고 이해 시험을 거친 뒤 교육 사례와 구분하여 제공한다.

### 사례·FAQ·용어의 개선

예시5개는 적중, 불일치, 판단 보류, 자료 정정, 결과 뒤에만 알게 된 정보로 재구성한다. 결과 전/후를 화면 단계로 나눠 사후정보가 처음부터 보이지 않게 한다. FAQ는 “무엇인가?” 나열보다 “저장했는데 안 보인다 / 폰으로 옮기고 싶다 / 결과를 잘못 적었다 / 취소된 경주는 어떻게 하나” 같은 과업형으로 쓴다. 용어는 최초 노출 시 짧은 뜻, 자세한 해설, 실제 예시로 연결한다.

## 9. 전체 수정 명세의 사용법

[64개 상세 명세](./implementation-specifications.md)를 개발 작업의 최소 단위로 사용한다. 각 CM 번호에는 **무엇을·왜·사용자 효과·어떻게 검증할지·대상 파일·기존 계획·예상 작업량**이 있다. 단순 제안 나열이 아니라 재현 및 완료 조건을 포함한다.

각 작업은 다음 순서로 닫는다.

1. 현재 공개판/소스판·문제 상태를 기록한다.
2. 실패 사례를 합성 데이터로 재현하는 검사를 먼저 만든다.
3. 기존 자료 호환을 보존하며 수정한다.
4. 자동 검사와 실제 브라우저 과업을 별도 기록한다.
5. 모바일 영향이면 유휴 Android 한 대에서 확인한다.
6. 운영자 결정이 필요한 것은 승인 증거 없이 통과시키지 않는다.
7. 검사한 같은 판을 공개한 후 핵심 흐름을 다시 확인한다.
